# Десктоп-клиент (Tkinter)

Тот же функционал, что и веб-панель Оркестратора, но нативное окно вместо браузера —
только стандартная библиотека Python, ставить ничего не нужно.

## Запуск

```bash
docker compose up -d          # из корня E:\plan — поднять 4 сервиса + postgres
python desktop-client/app.py  # из корня; либо из самой папки desktop-client
```

Подключается к уже запущенному стеку на `localhost:8001-8004` (те же порты, что и
у веб-версии). Если сервисы не подняты — индикаторы сервисов в шапке окна станут
красными, а действия будут падать с ошибкой соединения.

## Возможности

- Создание VK-аккаунтов, назначение тестовой (fake) сессии.
- «Войти в VK» — запускает `parser-service/scripts/vk_manual_login.py` в отдельной
  консоли для выбранного аккаунта: открывается настоящий Chromium, вручную логинишься
  в VK (с 2FA, если есть), возвращаешься в консоль, жмёшь Enter — сессия сохраняется
  в Data Service. Нужен `VK_ADAPTER_MODE=playwright` в `.env`, чтобы парсер/рассылка
  реально её использовали (иначе они работают в fake-режиме и в сессию не смотрят).
  Требует локально (не в Docker) `pip install playwright httpx` и
  `python -m playwright install chromium` — это зависимости самого скрипта логина,
  desktop-приложение по-прежнему обходится стандартной библиотекой.
- «Кому написали» — список отправленных сообщений; кнопка «Проверить ответы» запускает в
  Messaging Service фоновую проверку (`POST /inbox/check`, обход переписок в Playwright) и
  опрашивает её прогресс (`GET /inbox/check-status`, раз в 2с — как статус кампании) не
  блокируя окно; найденные ответы (текст + статус) видно прямо в таблице по завершении. Нужен
  `VK_ADAPTER_MODE=playwright` в `.env` messaging-service и сохранённая сессия аккаунта, иначе
  (fake-режим) ответов никогда не найдётся.
- Создание кампаний, выбор кампании в таблице — открывает панель с деталями.
- Живой опрос статуса (каждые 3с): фаза, статус, статистика, лиды.
- Сохранение шаблона сообщения (A/B) для выбранной кампании.
- Кнопка «Запустить» — как `POST /campaigns/{id}/start` в веб-версии.

## Устройство

Один файл `app.py`: `ApiClient`-функция на `urllib.request` (без `requests`/`httpx`,
чтобы не тянуть зависимости), Tkinter/ttk для UI, все сетевые вызовы — в фоновых
потоках (`threading.Thread` + `root.after(0, …)`), чтобы окно не подвисало во время
запроса. Те же правила именования и переводов статусов на русский, что и в
`orchestrator-service/app/static/index.html`.
